# Notes From The Underground

An [Obsidian](https://obsidian.md) plugin that scans your vault's markdown notes and displays them as a sortable, filterable, resizable table — pulling structured fields (Priority, Progress, Tags, Description, Link, Date) straight out of each note's content.

> The original Obsidian sample-plugin README has been kept at [`template-readme.md`](./template-readme.md) for reference.

## Scripts

Defined in `package.json`:

- **`npm run dev`** — Runs `node esbuild.config.mjs` in development mode. Bundles the plugin with esbuild and watches for changes, rebuilding `main.js` automatically as you edit source files.
- **`npm run build`** — Type-checks the project with `tsc -noEmit -skipLibCheck` (no output emitted, just error checking), then runs `node esbuild.config.mjs production` to produce an optimized, minified production build of `main.js`.
- **`npm run build:deploy`** — Runs `node deploy.mjs`, which first runs `npm run build`, then copies `main.js`, `manifest.json`, and `styles.css` into a local Obsidian vault's plugin folder for quick testing.
- **`npm run version`** — Runs `node version-bump.mjs` to bump the version number in `manifest.json` and `versions.json`, then stages both files with `git add` (used as part of a release/versioning workflow).
- **`npm run lint`** — Runs `eslint .` to lint the codebase using the project's ESLint configuration (including the `eslint-plugin-obsidianmd` rules).

## Build output (`main.js`)

`main.js` is the bundled plugin file that Obsidian actually loads — it's generated by esbuild from `src/main.ts` (see `esbuild.config.mjs`) and is gitignored, so it isn't committed to the repo. Run `npm run dev` or `npm run build` to produce it locally, or `npm run build:deploy` to also copy it (alongside `manifest.json` and `styles.css`) into a local vault's plugin folder.

## Source (`src/`)

- **`main.ts`** — The plugin's entry point (`NotesFromTheUndergroundPlugin`). On load, it registers the custom table view, adds a ribbon icon and a command (both named "Notes from the underground") that open or reveal the table view in a new workspace leaf.

- **`NotesTableView.tsx`** — Defines `NotesTableView`, an Obsidian `ItemView` (registered under the `notes-table-view` type). When opened, it reads every markdown file in the vault, parses each one with `parseNote`, and mounts the `NotesTable` React component into the view via `react-dom/client`'s `createRoot`. Unmounts the React root on close.

- **`Parser.ts`** — Exports `parseNote(file, content)`, which converts a note's raw markdown into a `NoteData` object:
  - The **title** comes from the first line if it's a `# Heading`, otherwise falls back to the file's basename.
  - The **path** is the parent folder's path, suffixed with `" Folder"` (or `"Root Folder"` for vault-root notes).
  - It scans the remaining lines for `Key: value` pairs matching `Priority`, `Progress`, `Tags`, `Description`, `Link`, and `Date` (case-insensitive), populating the corresponding fields. `Tags` is parsed as a comma-separated list (optionally wrapped in `[...]`).
  - If no explicit `Description:` property was found, everything after the last recognized property line is used as the description instead.

- **`NotesTable.tsx`** — The React table UI, built with [`@tanstack/react-table`](https://tanstack.com/table). Renders `NoteData[]` as an interactive table with:
  - Row selection checkboxes and a live "Total / selected" count.
  - Sortable columns (Path, Title, Priority, Progress, Tags, Description, Link, Date), with the Title column rendered as a link that opens the note via `app.workspace.getLeaf().openFile()`.
  - Per-column text filtering (with a custom filter function for the Tags array).
  - Column resizing (drag handles), reordering (◀ / ▶ move buttons per header), and a toggleable "Table Settings" panel for showing/hiding columns.

- **`reference.md`** — A sample note demonstrating the expected property format (`Priority`, `Progress`, `Tags`, `Description`, `Link`, `Date`) that `Parser.ts` looks for.
